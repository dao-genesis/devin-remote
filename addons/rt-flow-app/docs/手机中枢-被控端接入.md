# ☯ 手机中枢 · 被控端一行接入文档

> 本文供云端 Agent(Devin Cloud 等)与授权操作人员读取，经**手机**中转**远程操作已接入的电脑**。
> 任意电脑只需跑**一行 PowerShell**即可接入手机中枢——**无需在电脑上安装任何插件**。
> 端点 URL / session / token 随中继重启而变，**以本文档实时值为准**（见「断线自愈」）。

---

## 一、这是什么 · 与其他通道的区别（正本清源）

本仓有多条相互独立的远程通道，**切勿混淆**：

| 通道 | 谁在中转 | 操作对象 | 是否需装插件 |
|---|---|---|---|
| **手机中枢**（本文） | **手机 APK** | 经手机接入的**其他电脑**（被控端 agent） | 被控端**不需要**，只跑一行 PowerShell |
| **DAO Bridge**（`addons/dao-bridge`） | 电脑端插件 | **装了插件的那台整机** | 需要（电脑端） |
| **`/shell` 网页穿透**（dao-vsix 本体） | 电脑端插件 | 归一 Devin Cloud **网页**（六大板块） | 需要（电脑端） |
| **零账号 dao-relay**（`addons/dao-relay`） | Worker 中继（传输层） | 上述各通道的**承载管道** | 传输层，不直接操作 |

**手机中枢的本源**：把 DAO Bridge「一行 PowerShell 接入整机」的能力**搬到手机端中转**——
相对彻底的去中心化。手机既是被控端（自身 ADB/WebView），又是**中枢**（operator → 手机 → 被控 PC）。
协议、语义与 `addons/dao-bridge` 的 `WorkspaceServer` 完全一致（源级护栏见
`addons/rt-flow-app/test/phone-hub.test.js` 与 `addons/dao-bridge/dao-bridge-ext/test/hub.test.js`）。

三明治拓扑：

```
操作人员 / Devin Cloud
        │  (经中继 /relay/<session>，Bearer <token>)
        ▼
   手机中枢 (RelayService 常驻引擎 · relay-app.js)
        │  (connect / poll / result 长轮询队列)
        ▼
   被控电脑 agent (一行 PowerShell · 不装插件)
```

## 二、接入信息（实时值以本文档为准）

```
中枢端点(帧封装):  <endpoint>          例: https://<relay-host>/relay/<session>
中继 Token:        <token>            Header: Authorization: Bearer <token>
更新于:            <ts>
```

- 所有请求都是**帧封装**：向 `<endpoint>` POST 一个 JSON 帧
  `{"path":"/api/...","method":"POST","body":{...}}`，Header 带 `Authorization: Bearer <token>`。
- `/api/health` 免鉴权自证；其余端点经中继 token + 设备端 remoteOps 门禁双重鉴权。
- 手机中枢跑在 APK 的 `RelayService` 常驻前台服务里的引擎 WebView 单例中，**帧间状态天然持久**
  （内存队列/结果表），无需数据库。

## 三、被控端一行接入（PowerShell）

在**任意 Windows 电脑**（无需装插件）粘贴运行下面这一行的等价脚本即可接入。脚本由中枢
`GET/POST /api/bootstrap.ps1` **动态下发**（自动带当前 `<endpoint>` 与 token），核心流程：

1. 采集本机 `sysinfo`（hostname/username/platform/os_version/ps_version/capabilities）。
2. `POST /api/connect` → 领取 `agent_id` + **per-agent token**。
3. `while(true)` 长轮询 `POST /api/poll`（≤25s）取排队命令。
4. 在**隔离作用域**内执行命令（`$__daoCmd*` 前缀变量防被用户命令覆盖）。
5. `POST /api/result` 回传 `{stdout, stderr, exit_code, execution_time_ms}`。
6. 轮询/连接异常 → 自动 `re-connect`（token 轮换）后继续，**永不需要人工重发地址**。

> 取脚本：帧 `{"path":"/api/bootstrap.ps1","body":{"endpoint":"<endpoint>","token":"<token>"}}`
> → 返回 `{ "script": "...", "endpoint": "..." }`。把 `script` 存成 `.ps1` 直接跑，或
> `iex` 内联执行。脚本内不落任何账号密码/TOTP，仅含中继 token（等同接入口令）。

## 四、Agent API（操作人员 / Devin Cloud 侧）

全部经 `<endpoint>` 帧封装调用。`agent_id` 语义：**空 / `self` / `local` / `phone` = 手机本机**
（走 ADB/WebView shell）；**其它值 = 转发给该已接入电脑**。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/health` | GET | 自证 + `hub:{agents,online}` 计数（免鉴权） |
| `/api/connect` | POST | 被控端注册；返回 `agent_id`、`token`、`server_time`；重连同名 agent **轮换 token** |
| `/api/agents` | GET | 列全部被控端：`id/hostname/status(online·离线)/os/user/capabilities/last_seen/pending` |
| `/api/poll` | POST | 被控端长轮询取命令；`{id,token,timeout}`；**错 token → 401** |
| `/api/result` | POST | 被控端回传结果；`{agent_id,token,cmd_id,result}`；唤醒同步等待者 |
| `/api/heartbeat` | POST | 刷新 `lastSeen`（90s 无 poll/心跳判离线） |
| `/api/exec` | POST | **异步**下发；`{agent_id,type,...}` → 返回 `cmd_id`（未知 agent → 404） |
| `/api/exec-sync` | POST | **同步**下发；阻塞至结果或超时（默认 60s，上限 300s）→ 超时返回 504 |
| `/api/result-fetch` | POST | 查异步结果；`{agent_id,cmd_id}` → `pending` / `completed`(带 result) |
| `/api/broadcast` | POST | 向**所有在线**被控端各入队一条命令 |
| `/api/bootstrap.ps1` | GET/POST | 动态生成被控端一行接入脚本 |

### 命令规范化（跨平台）

`exec/exec-sync/broadcast` 的 body 支持 `{type,file,args,cmd,cwd}`，中枢按**被控端登记平台**
（`sysinfo.platform`）自动规范化为一条可执行命令串（移植自 dao-bridge `buildExecCommand`）：

- `type`：`shell`(默认) / `run`|`file`(执行程序·PowerShell `&` 调用或 `sh` 脚本) /
  `detached`|`spawn`(后台启动·Windows `Start-Process`／POSIX `nohup`) /
  `cmd`|`bat`(Windows `cmd.exe /d /c`·带 UTF-8 `chcp 65001`) / `sysinfo`(取机器信息)。
- Windows 用 `psq` 单引号转义，POSIX 用 `shq` 单引号转义，杜绝注入。

### 典型调用示例（伪码）

```jsonc
// 1) 列出已接入电脑
{"path":"/api/agents","method":"GET"}

// 2) 在某台电脑上同步执行并等结果
{"path":"/api/exec-sync","method":"POST",
 "body":{"agent_id":"BOX-A","cmd":"Get-Process | Select -First 5","timeout":30}}
// → {"status":"completed","cmd_id":"cmd_...","result":{"stdout":"...","exit_code":0}}

// 3) 异步下发 + 稍后取结果
{"path":"/api/exec","method":"POST","body":{"agent_id":"BOX-A","cmd":"ipconfig /all"}}
// → {"cmd_id":"cmd_..."} ; 之后:
{"path":"/api/result-fetch","method":"POST","body":{"agent_id":"BOX-A","cmd_id":"cmd_..."}}

// 4) 向全体广播
{"path":"/api/broadcast","method":"POST","body":{"cmd":"hostname"}}
```

## 五、安全模型

- **per-agent token 自证**：每台被控端持独立 token，`poll/result` 错 token 一律 401；
  重连轮换 token（旧脚本进程失效即自然吊销）。
- **中继 token = 接入口令**：持有它才能经 `<endpoint>` 下发命令；勿外泄、勿提交仓库。
- **E2E**：中继传输层沿用既有 AES-256-GCM 加密帧（`processFrame` 收发envelope），
  公共 broker 只见密文。本中枢逻辑在解密后的帧上运行，**不削弱**既有 E2E。
- **设备端门禁**：手机侧 `remoteOps` 开关 + Shizuku/uid2000 gating 决定是否放行真实执行。
- 文档、脚本、日志**均不含**任何密码 / TOTP / PAT / AES 密钥 / Cloudflare 凭证。

## 六、断线自愈（务必先读）

端点随中继重启而漂移，**永不找用户重发地址**：

1. 帧 `{"path":"/api/health"}` 2xx=活 → 直接操作。
2. 5xx/超时/DNS 失败 = 中继已轮换 → 重读本文档取新 `<endpoint>`（≤30s 内自动改写）。
3. 重读仍旧址 = 正在重建 → 每 30s 重读，最多 5 分钟；新端点 `/api/health` 通即接管。
4. 被控端脚本本身自带 re-connect：poll 抛错即重 `connect` 换新 token 续跑。

## 七、中继优先级与 Cloudflare（可选）

承载管道优先级（与 `AGENTS.md`「内网穿透是去中心化的」一致）：

1. **默认：零账号 `dao-relay`**（`…workers.dev/relay/<session>`，零配置、无需任何账号）。
2. 连不上 relay 才回退 **`cloudflared` 快速隧道**。
3. **可选**：用户自有**持久化 Cloudflare Worker/命名域名**（恒定地址）——仅当用户想要固定域名时，
   由其自行登录 Cloudflare 配置；**不是前置条件**，正常运行**无需** Cloudflare 登录，也无需 GitHub 登录。
4. 兜底：Route-C 公共 ntfy mesh（多 broker 加密直达，broker 只见密文）。

> dao-vsix 二合一插件另有「后端自动化用 GitHub 账号登录 Cloudflare → 生成 token → 建持久化 Worker」的
> **可选**助手（源级测试见 `core/dao-vsix/test/relay-gh-autologin.test.js`）：账号特定指纹/代理隔离，
> 最终登录/2FA/建 token 仍需用户手动，返回数据/日志无明文凭证。手机中枢**不依赖**它即可运行。
